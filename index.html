A bare-metal hypervisor with a friendly web UI

              
Proxmox Virtual Environment (PVE) is a Debian-based operating system you install directly onto a server. It combines two virtualization technologies — KVM for full virtual machines and LXC for lightweight Linux containers — and manages both from a web interface on port 8006.

              
It's free and open-source (AGPLv3). An optional paid subscription gives access to the enterprise update repository and support, but the no-subscription repository works great for home labs.

            

            
    
              
  • 🖥️ Web UI at https://<your-ip>:8006
    • 
              
  • 🧱 KVM virtual machines + LXC containers
    • 
              
  • 💾 ZFS, LVM-thin, Ceph, NFS, SMB and more
    • 
              
  • 🔁 Built-in snapshots, backups & live migration
    • 
              
  • 🛡️ Integrated firewall & user permissions

🖥️ Virtual Machine (KVM)

              
    
                
  • Full, isolated computer with its own kernel
    • 
                
  • Runs any OS: Windows, BSD, Linux, appliances
    • 
                
  • Supports PCIe passthrough (GPUs, HBAs, NICs)
    • 
                
  • Stronger isolation, more overhead
    • 
              

              
Best for: firewalls (OPNsense), NAS OSes (TrueNAS), Home Assistant OS, Windows, Docker hosts.

            

            

              
📦 Container (LXC)

              
    
                
  • Shares the Proxmox host's Linux kernel
    • 
                
  • Linux-only, boots in seconds
    • 
                
  • Very low RAM & CPU overhead
    • 
                
  • Easy bind-mounts of host storage
    • 
              

              
Best for: lightweight Linux services such as Pi-hole, reverse proxies, media servers, small databases.

            

          

        


        

          
Pick storage that fits your hardware

          

            
ZFS
Checksums, snapshots, compression and software RAID. Loves RAM and ECC memory. Great default for data you care about.

            
LVM-thin
The installer's default on a single disk. Thin provisioning and snapshots with minimal overhead.

            
Ceph
Distributed, replicated storage across 3+ nodes. Powerful, but needs fast networking and several disks.

            
NFS / SMB
Mount shares from a NAS for ISOs, backups, or bulk media.

            
Directory
Any mounted filesystem path. Simple and flexible for ISOs and backup files.

            
Tip
Keep the OS/VMs on fast SSDs and bulk media on large HDDs.

          

        


        

          

            

              
The 3-2-1 rule

              
Keep 3 copies of your data, on 2 different types of media, with 1 copy off-site. Snapshots are not backups — they live on the same disk.

              
Proxmox includes vzdump for scheduled backups of any VM or container. For deduplicated, incremental, and verifiable backups, pair it with the free Proxmox Backup Server (PBS).

            

            
# Back up container 101 to the "local" storage
vzdump 101 --storage local --mode snapshot --compress zstd

# Restore it as a new container 201
pct restore 201 /var/lib/vz/dump/vzdump-lxc-101-*.tar.zst

          

        


        

          

            

              
Linux bridges & VLANs

              
By default Proxmox creates a bridge called vmbr0 attached to your physical NIC. Every VM and container connected to it appears on your LAN like a separate machine.

              
Make the bridge VLAN-aware to put services on separate networks (e.g. IoT, DMZ, management) using a VLAN tag on each guest's network device.

            

            
# /etc/network/interfaces (excerpt)
auto vmbr0
iface vmbr0 inet static
    address 192.168.1.10/24
    gateway 192.168.1.1
    bridge-ports eno1
    bridge-stp off
    bridge-fd 0
    bridge-vlan-aware yes
    bridge-vids 2-4094

          

        


        

          
From one box to a cluster

          
Join multiple Proxmox nodes into a cluster to manage them from one UI and migrate guests between them. For high availability (HA) you need quorum — at least 3 votes. Two-node setups can add a small external QDevice (even a Raspberry Pi) as the tie-breaker.

          
# On the first node
pvecm create homelab
# On each additional node
pvecm add 192.168.1.10
# Check status
pvecm status
